## 页面与组件清单（厂商端） 
### 1. 全局页面地图（Page Map） 
采用树状结构，标注页面ID、名称、模块归属和跳转关系。所有页面统一采用桌面端宽度 **1440px**，高度按内容自适应（Figma中可用Frame高度自定义）。

```plain
00-公共模块
├── 00A-注册页（选择角色）
│   ├── 选“我是厂商” → 01A
│   └── 选“我是采购方” → 02A（自动登录）
├── 00B-登录页
│   ├── 厂商登录 → 01B
│   └── 采购方登录 → 02A
└── 00C-首页（可选，Demo可跳过）

01-厂商端
├── 01A-厂商注册详情页
│   └── 注册成功 → 01B
├── 01B-厂商控制台
│   └── 入口 → 01C
├── 01C-能力录入页（三步向导）
│   ├── Step1：模板化表单
│   ├── Step2：自由文本
│   ├── Step3：文档上传
│   └── 提交材料 → 01D
└── 01D-能力档案页（只读）
    └── 返回 → 01B（可随时回看）

02-买家端
├── 02A-需求对话Agent页
│   ├── 确认需求 → 02B
│   └── 修改需求 → 02A（带回上下文）
└── 02B-匹配结果页
    └── 修改需求 → 02A

03-管理员后台
├── 03A-管理员登录页（独立，或复用00B但选择管理员角色）
│   └── 登录成功 → 03B
├── 03B-数据概览页（Dashboard）
│   ├── 快捷入口 → 03C / 03D
│   └── 卡片点击可跳转对应列表页
├── 03C-需求与匹配查看页
│   └── 点击行 → 抽屉/详情页（需求详情）
└── 03D-厂商产品查看页
    └── 点击行 → 详情页（厂商能力档案）
```

**设计提示**：在Figma中，可将每个页面建为一个顶层Frame（1440×自适应），页面间的跳转关系用Prototype中的连线表示，方便演示时点击流转。

**设计提示**：管理员后台采用经典的“侧边导航+顶部面包屑”布局，与厂商控制台风格一致但配色可区分（如深蓝色主题）。所有列表页支持分页、搜索、筛选。在Figma中，可使用同一套后台组件库。

| **Figma建议** | 使用Auto Layout纵向排列表单元素，间距8px/16px；按钮用Primary Variant；错误状态用Error Variant的输入框组件。 |

## 页面与组件清单（买家端） 
**设计提示**：买家端流程极简——注册后直接进入02A，完成需求描述后跳转到02B。在Figma原型中，02A到02B的跳转可用Overlay或换帧实现，建议用换帧（Navigate To）并带上过渡动画（Dissolve或Move In），模拟页面切换感。

### 1. 买家端页面清单（Page Spec） 
#### 02A · 需求对话Agent页 
| 属性 | 说明 |
| --- | --- |
| **对应PRD** | 2.1 自助注册/登录、2.2 开场引导、2.3 动态选项、2.4 自由输入、2.5 需求萃取完成与需求档案管理、2.8 会话与需求匹配历史管理 |
| **布局结构** | 典型聊天界面：顶部标题栏（“需脉AI选型助手”+“新建会话”入口），中间主区域为对话气泡流（左侧Agent，右侧用户），底部固定输入栏（文本框+发送按钮+“完成需求描述”按钮）。对话进行中，右侧或底部可悬浮一个“当前需求摘要”面板（实时更新）。 |
| **核心组件** | `COMP-017`对话气泡、`COMP-018`选项按钮组（动态弹出）、`COMP-019`需求档案卡片（确认用）、`COMP-020`悬浮摘要面板、`COMP-021`输入框（带发送功能）、`COMP-002`按钮（复用，用于“提交匹配”等） |
| **关键交互** | ① **开场引导**：页面加载时，Agent自动发送第一条消息（带选项按钮），用户点击选项后，Agent自动回复下一条并弹出新选项；   ② **自由输入**：用户在输入框打字并发送，消息以用户气泡出现在右侧，Agent回复确认气泡；   ③ **动态选项**：选项按钮组出现在Agent消息下方，点击后按钮变为选中态，同时输入框自动填入该选项文字（可追加）；   ④ **萃取中改口**：用户输入“不对，我要Android”，Agent仅更新当前需求槽位与悬浮摘要面板（不生成新档案、不触发重新匹配）；   ⑤ **完成与提交**：完成判定双通道——Agent在核心参数齐备后主动提示“确认完成？还是继续补充？”，或用户点击“完成需求描述”；确认后插入`COMP-019`需求档案卡片，点击“提交匹配”跳转02B；已确认档案修改生成新版本并提示“是否重新匹配”；   ⑥ **会话管理**：顶部可“新建会话”或进入“我的会话”查看历史；对话自动保存，刷新/断网/重登后恢复；每次“提交匹配/重新匹配”生成需求匹配快照，可在“历史匹配”回看。 |
| **数据绑定** | 完整对话过程存入 `conversations.conversation_history`；每次确认匹配生成需求匹配快照存入 `buyer_requests`（含 `conversation_id`、`version`、确认时的 `structured_demand`）；悬浮面板实时显示当前提取的字段。 |
| **异常状态** | ① 输入为空时发送按钮禁用；② 网络错误时发送失败，气泡显示红色感叹号，可重试；③ 产品类型（品类锚点）未指定时，“提交匹配”按钮置灰，提示“请先明确要寻找的产品类型”；其余字段未指定不影响提交（按通配）。 |
| **Figma建议** | 对话流使用Auto Layout竖向排列，气泡之间间距8px；Agent气泡左对齐，用户气泡右对齐；选项按钮组使用Auto Layout横向换行，每个按钮是一个Variant（Default/Selected/Disabled）；悬浮摘要面板可用一个固定在右侧的Frame，宽度300px，内部用Auto Layout纵向排列字段；整个页面Frame高度设为900px，对话区域可滚动（Figma中可用Scrolling Overflow模拟）。 |
