### 一、产品定位与演示目标 
**一句话定义**：需脉枢纽种子轮演示原型是一个**B2B代工制造供需智能语义匹配PoC**，通过自然语言理解与混合输入方式，让代工企业完整表达隐性制造能力，让采购方精准描述复杂需求，并由大模型实时完成语义匹配，返回带匹配理由的工厂列表。

**演示目标**：让投资人在3分钟内理解“语义匹配 vs 关键词搜索”的本质差异，并确信“纯净、去营销化”的供需连接是可行且高价值的。

**演示成功标准**：

+ 现场可用真实厂商数据跑通完整匹配链路
+ 匹配理由的可解释性直观展示AI的理解深度
+ 支持需求修正，体现对话Agent的智能和灵活

### 二、目标用户与演示场景 
| 角色 | 在Demo中的行为 |
| --- | --- |
| **代工厂商（供给端）** | 已预先导入真实共创会员资料（30~50家），也可现场演示注册/上传流程 |
| **采购方（需求端）** | 通过对话Agent描述复杂需求，支持中途修正，获取匹配结果 |
| **管理员** | 简单后台查看用户需求、厂商产品、匹配日志（用于演示数据真实性和可追溯） |
| **演示操作者** | 创始人，负责切换账号、引导流程、展示真实数据效果 |


**锁定垂直行业**：消费电子代工（机顶盒、智能音箱、IoT设备等），需求参数复杂、代工能力差异大，投资人易理解。

### 三、核心功能模块与页面结构 
#### 模块1：厂商端——能力发布与入库（供给端） 
| 页面 | 交互细节 |
| --- | --- |
| **1.1 自助注册** | 手机号/邮箱注册，选择“我是厂商”，填写企业基本信息 |
| **1.2 能力录入（混合模式）** | 三步引导：   ① **模板化表单**：行业、工艺、认证、设备、擅长场景（下拉多选）   ② **自由文本**：富文本框，自然语言描述隐性能力   ③ **文档上传**：支持PDF/PPT/Word（设备清单、案例、证书） |
| **1.3 AI解析与预览** | 大模型自动提取结构化字段，生成“AI能力档案”预览，厂商可确认 |
| **1.4 审核状态** | 显示审核状态（Demo中可设为自动通过或由管理员一键审核） |


**数据说明**：Demo中预先导入真实共创会员的脱敏资料，确保匹配结果有真实参考价值。现场也可演示新厂商注册流程。

#### 模块2：买家端——需求描述与匹配（需求端）【更新：支持需求修正】 
| 页面 | 交互细节 |
| --- | --- |
| **2.1 自助注册/登录** | 选择“我是采购方”，简化流程 |
| **2.2 需求对话Agent（核心）** | 聊天式UI，系统主动引导+用户自由输入：   • 开场：Agent自我介绍，询问需求类型   • 多轮引导：动态弹出选项（如“需要哪些操作系统？”→按钮组）   • 自由补充：用户可随时输入大段自然语言   • **【新增】需求修正**：用户可随时说“不对，我需要Android而不是Linux”，Agent立即更新需求摘要，并提示“需求已更新，是否重新匹配？”   • 需求确认：生成结构化需求摘要，用户确认后提交 |
| **2.3 匹配结果页（精简列表）** | 顶部“为您找到N家匹配的工厂”，列表项：   • 工厂名称、所在地、一句话摘要   • 匹配度百分比   • 点击展开详情 |
| **2.4 匹配详情（展开态）** | 顶部显示子分数副行（“语义相似度82% · 参数命中5/6”），下方按判定分三组：   • ✅ **匹配项**：绿色标签，列出一致参数   • ⚠️ **需协商/未声明**：黄色标签，如“交期30天 vs 45天（需协商）”“ISO13485（厂商未声明）”   • ❌ **不匹配项**：红色标签，关键参数不符时顶部出红色警示条   • **AI评语**：一段话总结匹配优劣（算法定义见《产品需求设计》阶段7） |


#### 模块3：匹配引擎（后台逻辑，需可见效果） 
+ **大模型**：调用当前最强模型（GPT-4o或Claude 3.5 Sonnet），负责：
    - 解析厂商自由文本/文档，提取结构化能力标签
    - 理解买家对话中的复杂需求，生成结构化需求向量
    - 计算供需匹配度，生成匹配理由和可解释性文本
+ **数据基础**：真实共创会员资料预导入，存储在PostgreSQL（结构化）+ 向量数据库（嵌入）
+ **匹配算法**：双通道打分——语义相似度（向量，权重0.4）+ 参数命中率（LLM逐参数判定，权重0.6），综合匹配度=0.4·语义+0.6·参数命中；关键参数（产品类型/OS/认证）不符时封顶50%并红色警示；过滤阈值30%；Demo阶段不训练专属模型，但效果要惊艳（完整算法定义见《产品需求设计》阶段7）

| **4.2 用户需求查看** | 列表展示所有买家提交的需求摘要，可点击查看完整对话历史和结构化需求 |

| 步骤 | 操作 | 投资人看到的效果 |

### 五、技术实现建议（PoC级别，更新） 
| 层面 | 建议方案 |
| --- | --- |
| **前端** | React/Vue + 聊天UI组件库，1~2周出高保真界面 |
| **后端** | Python FastAPI，对接大模型API，处理文件解析和向量存储 |
| **大模型** | GPT-4o（多模态，支持文档理解）或 Claude 3.5 Sonnet |
| **数据存储** | PostgreSQL（结构化数据）+ 向量数据库（Pinecone/Milvus） |
| **文档解析** | Unstructured/LayoutParser提取PDF/PPT文本，再喂给大模型 |
| **对话状态管理** | 前端维护对话历史，后端用大模型维护结构化需求槽位，支持动态更新 |
| **部署** | 云端部署，确保投资人可远程访问体验 |
| **数据准备** | 提前收集30~50家真实共创会员资料，清洗脱敏，导入系统 |
