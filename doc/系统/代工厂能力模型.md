# 需脉枢纽 · 代工厂能力模型（领域输入）

> 版本：v1.0 ｜ 状态：领域模型（作为《AI核心总体架构设计v2》能力维度本体的领域输入） ｜ 更新：2026-08-15
>
> 本文档是**代工（OEM/ODM/EMS）能力的领域模型**，回答四件事：代工覆盖哪些行业、不同行业能力的共性与差异、
> 具体有哪些能力项、能力项如何归类。它是：
> - 《AI核心总体架构设计v2》第 4 章**能力维度本体**的领域依据（填充骨架的血肉）；
> - 厂商入驻表单 / 能力萃取 Prompt / Agent 追问槽位 / 匹配判定的**共同领域来源**。
>
> 与本模型冲突的细化设计，以本模型的归类法为准（两轴正交）。

---

## 1. 代工业态（按合作深度）

| 业态 | 含义 | 能力侧重 |
| --- | --- | --- |
| **OEM** | 纯代工/来图加工：品牌方给设计，工厂按图生产 | 制程、产能、质量、认证、商务 |
| **ODM** | 设计+代工：工厂提供方案与生产 | + 研发设计、打样、模具 |
| **JDM** | 联合设计：双方共建方案 | + 协同研发、快速迭代 |
| **EMS** | 电子制造服务：PCBA/组装/测试/整机集成 | 电子制程、测试、供应链 |

> 合作深度决定了"研发设计/ODM"能力是否成为关键判定项。本平台当前聚焦 **EMS 型消费电子代工**，但模型须能容纳全部业态。

| 行业 | 代表品类 | 行业特有**硬**能力 | 行业特有**软**能力 | 平台聚焦度 |
| --- | --- | --- | --- | --- |
| **消费电子** | 机顶盒 / 智能音箱 / IoT / 手机 | OS、主控平台、无线、麦克风阵列、SMT/PCBA | 声学调校、三防工艺经验 | ★ PoC 聚焦 |

| 汽车 | 车规部件 | IATF16949、PPAP、全追溯 | 车规量产经验 | 后续 |
| 工业设备 | 控制柜 / 结构件 | 钣金、机加工、防护等级 | 定制化集成经验 | 后续 |
| 塑胶/注塑 | 外壳 / 结构件 | 模具、吨位、材料 | 模具开发经验 | 后续 |

## 3. 能力项全景（11 组）

> 值形态：enum（枚举多选）/ number（数值）/ text（自由文本）——决定匹配判定方式（规则/语义）。
> 硬/软：硬=可结构化精确匹配；软=语义匹配（向量/LLM）。

| 组 | 能力项 | 值形态 | 硬/软 |
| --- | --- | --- | --- |
| ① 制程能力 | SMT / DIP / 组装 / 测试 / 注塑 / CNC / 表面处理 / 包装 | enum | 硬 |
| ② 产品品类 | 能做的产品类型（机顶盒/音箱/医疗/汽车…） | enum | 硬 |
| ③ 技术平台 | OS / 主控 / 无线 / 声学 / 传感器 / 嵌入式 | enum | 硬 |
| ④ 资质认证 | 体系（ISO9001/13485/16949…）+ 产品（CCC/CE/FCC/SRRC…） | enum | 硬 |
| ⑤ 产能规模 | 月产能、产线数、厂房面积、员工数、年产值 | number | 硬 |
| ⑥ 供应链 | 物料自备/来料、元件供应、仓储物流、交付 | enum/text | 硬+软 |
| ⑦ 质量可靠性 | 质量体系、检验设备（AOI/SPI/X-ray）、老化测试、直通率 | enum/number | 硬 |
| ⑧ 研发设计 | ODM 能力、结构/电子/软件团队、打样、模具 | enum/text | 软 |
| ⑨ 商务条件 | **MOQ、交期**、代工模式（OEM/ODM/JDM/EMS）、付款条件 | number/enum | 硬 |
| ⑩ 行业经验 | 过往案例（欧美市场/医疗/三防）、客户类型、服务年限 | text | 软 |
| ⑪ 合规ESG | RoHS/REACH、验厂（BSCI/SEDEX）、出口资质 | enum | 硬 |

## 4. 归类方法（核心）：两个正交轴

```
轴A · 性质（决定怎么匹配）
   硬能力：认证/MOQ/交期/产能/制程/平台/合规 → enum、number → 精确(rule)
   软能力：研发经验/案例/擅长领域/服务年限  → text → 语义(semantic/向量)

轴B · 作用域（决定怎么萃取与配置）
   通用能力：所有行业共有（ISO9001/MOQ/交期/产能/质量/供应链/商务/合规）
   品类能力：行业特有（电子=OS/无线/声学/SMT；医疗=ISO13485/洁净；汽车=IATF16949…）

        ┌───────────────┬────────────────┐
        │ 通用·硬        │ 品类·硬         │ → enum/number，rule 判定
        │ (认证/MOQ/交期) │ (OS/无线/SMT…)  │
        ├───────────────┼────────────────┤
        │ 通用·软        │ 品类·软         │ → text，semantic/向量
        │ (服务年限/案例) │ (声学调校经验…) │
        └───────────────┴────────────────┘
```

**归类法 → 本体映射**（《AI核心总体架构设计v2》第 4 章）：

| 象限 | provenance | value_type | 匹配方式 |
| --- | --- | --- | --- |
| 通用·硬 | general | enum / number | rule（集合/数值/方向） |
| 品类·硬 | category | enum / number | rule（品类配置化） |
| 通用·软 | general | text | semantic（LLM/向量） |
| 品类·软 | category | text | semantic / soft 软层 |

**该归类同时决定**：
1) **需求侧能问什么**：Agent 追问槽位 = 通用能力 + 当前品类能力（买方可声明的子集）；
2) **厂商侧能萃什么**：提取器维度 = 同一份能力项；本体外的 → soft 软层（自由标签+摘要+原文块）；
3) **匹配能比什么**：硬项精确、软项语义，且与严格度（strict/partial/best-effort）结合。

## 5. 双侧映射（需求侧可声明 vs 厂商侧入驻需提供）

> 同一能力项在两侧的形态不同：需求侧是"要求/偏好"，厂商侧是"能力/供给"。

| 能力项 | 需求侧（买方可声明） | 厂商侧（入驻/萃取） |
| --- | --- | --- |
| ① 制程 | 需哪些工艺（SMT/组装/测试） | 具备哪些制程 |
| ② 品类 | 要做什么产品（品类锚点） | 能做什么产品 |
| ③ 技术平台 | 要什么 OS/主控/无线/声学 | 支持哪些平台 |
| ④ 认证 | 必须/希望有哪些认证 | 已具备哪些认证 |
| ⑤ 产能 | 需要多大产能/月产能 | 具备多大产能 |
| ⑥ 供应链 | 是否来料加工/代采 | 物料/供应能力 |
| ⑦ 质量 | 质量要求/可靠性测试 | 质量体系与设备 |
| ⑧ 研发 | 是否需要 ODM/打样 | ODM/研发团队能力 |
| ⑨ 商务 | **MOQ、交期、预算** | **MOQ、交期**、起订弹性 |
| ⑩ 经验 | 需要什么经验（欧美/医疗/三防） | 过往案例/擅长领域 |
| ⑪ 合规 | 出口合规/环保要求 | 认证与验厂资质 |

> **匹配的核心场景**：需求侧 ⑨（MOQ/交期/预算）+ ④（认证）为最常见硬匹配点；⑩（经验）+ ⑧（ODM）为常见语义匹配点。

## 7. 与现有实现的差异

| 现有 | 能力模型应覆盖 |
| --- | --- |
| 需求侧 9 通用 + 3 品类字段 | 11 组能力项中"买方可声明"子集（双向映射表第 5 章） |
| 厂商侧 7 硬 + 3 软维度 | 11 组能力项全量（供应商全画像，含研发/供应链/质量设备/商务模式） |
| 无研发/供应链/质量设备/商务模式维度 | ⑧⑨⑩ 等缺失项补入 |
| 无行业扩展机制 | 行业矩阵 → 品类配置化 + soft 兜底 |
