# 需脉枢纽 · 系统开发计划

> 版本：v1.0 ｜ 状态：指导开发 ｜ 更新：2026-08-08
>
> 本计划基于《系统架构设计.md》《核心系统需求.md》《前端设计规范.md》《用户画像设计.md》制定，是**严格可执行的开发蓝本**：每个阶段有目标、任务清单（含验收与工时）、阶段验收（DoD）；开发时按任务编号勾选推进。
>
> **计划口径**：与《系统架构设计》第 12.1 里程碑一致，总工期 **~32 天**（M1-M7）；技术栈、目录结构、接口契约、数据模型均以架构文档为准。

## 1. 总览

### 1.1 目标与原则
1. 交付**真实可演示**的 PoC：真实数据、真实运行、真实效果，无黄金路径、无演示专用行为；
2. 采用**模块化单体 + 进程内异步任务**（ADR-02/09），单机 docker-compose 可一键运行；
3. 全程 **Code-First 契约 + 契约先行**（ADR-10/11）：M1 先定义全部接口层（Pydantic + router stub）产出完整契约；前端**基于契约派生 mock 自测**，后端后续填实现，前后端真正并行；
4. 每个域模块遵循“**models → schemas → service → router → tests**”五步完成，测试伴随；
5. **UI-first（前端优先）**：M1 完成全部前端页面并基于 mock 体验、确认 **UI 冻结基线**；后续功能开发不再调整 UI（前端规范 P0/P1 全部 + P2 视需）。

### 1.2 最终交付物
- monorepo 工程（`frontend/` + `backend/` + `infra/` + `doc/`），docker-compose 一键启动；
- 预置 **100 家 passed 厂商能力档案** + 领域知识库 + 演示账号的种子数据；
- 端到端演示脚本 + 验收清单（见第 11 章）。

### 1.3 里程碑总览
| 阶段 | 主题 | 工期 | 主要交付 | 依赖 |

### 1.4 团队与协作
- 按 1~2 名开发者假设排程；**前端页面集中在 M1 完成**（基于 mock 体验），后端各里程碑实现后对接真实 API；

- 每日按任务编号记录进度（见第 13 章）。

## 2. 工程与环境约定（贯穿全程）

### 2.1 环境与工具
| 项 | 版本/工具 |
| --- | --- |
| Python | 3.12 + FastAPI + SQLAlchemy 2.0(async) + Pydantic v2 + LangGraph |
| Node | 20+；pnpm workspace（前端） |
| 数据 | PostgreSQL 16、Milvus standalone、对象存储（本地卷） |
| 容器 | Docker Desktop + docker-compose |
| 契约 | FastAPI 自动产出 openapi.json；orval / openapi-typescript 生成前端 api |
| 文档 | 本计划 + 架构/需求/前端/画像四文档 |

### 2.2 分支与提交流程
- 分支：`main`（可运行）← `feature/Mx-Tx-<域>`；PR 合并；
- 提交信息：`M2-T2.1: auth 域注册登录` 形式，便于按计划追溯；
- 每个任务合并前必须通过：本任务测试 + 契约快照无 diff。

### 2.3 开发顺序纪律
0. **接口层先行（契约先行）**：M1 已定义全部接口 schema + router stub；后续各阶段只填充 handler 实现，**禁止新增未在契约层的接口**（确需新增时先回契约层更新）；
1. 每个域模块固定顺序：`models → schemas → service → router → tests`；
2. **改任何接口**：同步更新该接口测试 → 导出 openapi → 前端重新生成（类型 + mock）→ 前端编译通过；
3. AI 相关调用一律走 `app/llm/client.py` 统一封装（超时/重试/日志/Token 记录），禁止散落直连；
4. 异步任务统一走 `core/queue.py` 的 `TaskQueue` 抽象（进程内实现），不绕开队列。

### 2.4 任务完成定义（DoD）
- [ ] 代码实现并自测通过（相关单元/集成测试绿）；
- [ ] 接口已同步到 openapi.json（契约无 diff）；
- [ ] 前端（若涉及）编译通过、联调可用；
- [ ] 涉及文档引用处已同步（如需）。

## 10. 编码规范与测试约定

### 10.1 后端（Python）
- **风格**：ruff + mypy；类型标注完整；Pydantic v2 定义全部请求/响应；
- **ORM**：SQLAlchemy 2.0 async；模型集中在 `app/db/`，域内 `models.py` 引用；
- **AI 封装**：一律经 `app/llm/client.py`（超时/重试/日志/Token 计数）；Prompt 在 `llm/prompts/` 独立维护；
- **异步**：经 `core/queue.py` 的 `TaskQueue`；任务幂等、结果落库后由前端轮询。

### 10.2 前端（TS）
- TS strict + ESLint + Prettier；组件按 COMP 映射表用 Naive UI（前端规范 3）；
- 页面与路由按前端规范 4；设计 Token 经 `packages/tokens` 引用；
- 交互遵循前端规范 7（骨架屏/三态/状态徽标/警示条）。

### 10.3 测试
- **单元**：pytest（service/合并器/打分）；Vitest（组件/状态）；
- **集成**：httpx AsyncClient 打真实 FastAPI（PG/Milvus 用 compose 起）；
- **端到端**：M7 演示脚本即回归脚本；
- **契约**：CI 校验 openapi 快照 == 后端输出（无 diff），前端生成物不手改。

### 10.4 契约纪律（贯穿）
改接口 → 更新测试 → 导出 openapi → 前端重新生成 → 前端编译通过 → 提交。
